# AGENTS.md

## Public repo / secrets
- Everything tracked and every diff is public: never commit secrets, `.env`, private URLs, personal/customer/prod data; use fake placeholders. Check `git status` and the staged diff before committing; never force-add ignored files. If private data shows up, stop and alert the maintainer.
- Commit messages, PRs, issues, review replies are public too: describe test results in words (no tool output); no business metrics (analytics, traffic, conversion, signups, revenue, stars); nothing identifying a person/machine/account (local paths, usernames, hostnames, signing identities, legal entity names, Apple Team IDs, API key/issuer/tenant IDs, emails, or the accounts/machines/files secrets came from). Naming the secrets a workflow reads is fine; use placeholders for values.

## Architecture
- One product across web, Electron desktop (hosts the web UI), Expo mobile. Shared behavior/contracts/API logic/reusable UI go in packages; only truly native navigation/storage/permissions/interactions are platform-specific. Core workflows cover every applicable surface or degrade safely for an explicit reason.
- No hosted vendor required. LLMs, sandboxes, memory, voice, integrations, future services are optional, behind provider-neutral interfaces. Vendor SDKs/config/translation only in adapters and composition roots.
  - Each provider lives in `packages/adapters/src/providers/<family>/<id>/`, never imports another provider's folder; shared code goes outside `providers/` under a non-vendor name (checks: import-boundaries, `no-vendor-files-outside-providers`).
  - Vendor names never appear outside adapters (contracts, settings, DB columns, routes, UI, copy), even if only one provider supports a feature. Outside adapters a provider id is an opaque string: never branch on it or sniff provider-specific strings; declare capabilities in the provider descriptor/capabilities in `packages/adapters`; read labels, settings fields, defaults from the descriptor the server sends (check: `no-vendor-names-outside-adapters`).
  - User-picked names are product data, not leakage: messaging apps, model providers/protocol ids, integrations catalog, each in its catalog file in `packages/core/src`.
  - New providers reuse shared contracts and deterministic offline conformance tests. Rarely-needed packages load via dynamic `import()` only when configured (import-boundaries flags server code that also imports one statically) and must be reputable packages or a trusted, established vendor's direct API (not e.g. a brand-new startup's sandbox).
- Configure compatible providers/models via shared connection settings and standard protocol capabilities; no provider- or model-specific env vars when the generic connection can express it.
- Runtime layout: web-server-only code (dev/preview/standalone server, build plugins) in `apps/web/server`; desktop code in `apps/desktop/src/main`, `preload`, or `setup-renderer` by process; Node-only core modules behind `@rakazo/core/node/*`, out of the main barrel. Browser/preload/renderer never import server or main-process code.
- Group files by topic (`packages/core/src/<topic>/`, matching folders elsewhere); core's source root holds only `index.ts` (check: `core-topic-folders`).
- Keep code simple: reuse primitives, one source of truth, no duplication/unused flexibility/speculative abstraction. Add an interface only for a real external/platform boundary; a provider-neutral interface always counts.
- Prompts: authored model instructions and pure prompt builders in `*.prompt.ts`; tool names/descriptions/input schemas together in `*.tool-definition.ts`; execution and authorization stay outside definition files. Fingerprint discovers them automatically; see `docs/prompts.md`.
- Security-sensitive: auth, secrets, sandbox boundaries, host commands, integrations. New sealed-value column (name contains `cipher`) goes in `packages/adapters/src/secrets/secret-holder-columns.json`: `checked` if it can hold a remote store entry (write-ahead cleanup looks up every listed column before deleting), `neverRemote` if never. Tests deterministic and offline by default.
- Dependency security audits include build/release dependencies and assert workspace package coverage; scanning only the package-manager YAML is not a pass.

## Code conventions
- Format with Biome (`pnpm format` or `pnpm exec biome check --write <files>`); never Prettier.
- Top-level `import type`, never inline type imports. Dynamic `import()` only for necessary deferred loading.
- Startup size budget enforced after build by `scripts/checks/bundle-size.mjs` (web JS/CSS before first paint; desktop main bundle): lazy-load heavy/rare code.
- Mechanically checkable convention → add a check in `scripts/checks/` (see its README) and keep the rule here. Run `pnpm checks` before pushing.
- Shared primitives (checks reject hand-rolled copies):
  - Server waits/retries: `retry`, `pollUntil`, `deadlineSignal`, `abortableDelay`, `parseRetryAfter` from `@rakazo/core`.
  - Ignorable failure: `bestEffort(label, promise)` from `@rakazo/logging`, never silent `.catch(() => undefined)`; if caller needs to know, handle/propagate, catching only the specific condition.
  - Start a run: `wakeRun` from `@rakazo/adapters`.
  - Long work across processes: `withLease(prisma, key, options, work)` from `@rakazo/db` (fences, renews, releases); check rejects new lease/claim/attempt columns.
  - JSON column reads: `readJsonColumn(schema, value, { table, column, id }, "reject" | { fallback })` from `@rakazo/db`, never a cast. `"reject"` when the value is required; fallback when an older shape is expected and harmless. Reject stops work on that row only: multi-row passes catch `JsonColumnMismatchError`, skip the row without guessing, report via `reportJsonColumnOnce`. A fallback is a display default, not what the row holds: never write it back or decide access from it.
  - Message blocks: `storedMessageBlocks` to read; `readMessageBlocks` (also reports dropped entries) where a missing block decides something, taking the restrictive answer if entries were dropped; `changeMessageBlocks` to write back.
  - Computer provider support: declare in the provider's `*-computer.ts` descriptor, read via `sandboxKindCapabilities(kind)`; shared code never branches on provider id.
  - Timers/listeners in web/mobile components and hooks: `useTimeout`, `useNow` from `@rakazo/chat-ui/hooks`; on web `useEventListener` from `apps/web/src/lib/use-event-listener.ts`; never raw `setTimeout`/`setInterval`/add-remove listener pairs in effects.
  - Mobile screens: read via helpers in `apps/mobile/lib/query/query.ts` and `useScreenQuery`; save with `useSave` (owns pending, failures, double taps, late answers), writing only through the `send` its `save` receives. A screen editing a named Space/the account (not the selected Space) gives its reads (`targetRpcQuery`) and `useSave` the same `target`. Convert a whole screen, never part.
  - Mobile headers: `useScreenHeader` from `apps/mobile/lib/navigation/screen-header.tsx` (title + one trailing action; always runs latest `onPress`); never `navigation.setOptions` in an effect for those.
  - Web saves: `useSave` from `apps/web/src/lib/query/query.ts`, same contract: write only through the client its `save` receives, list reads made stale in `stale`, no saving/pending/error `useState` beside it.
  - Tests: hold a call open with `deferred()`, run due timers and queued promise callbacks with `flush()` (both from `@rakazo/core/test-async`; `primitives/async.test-support.js` inside core); wait on conditions with `vi.waitFor`/`vi.waitUntil`; never hand-captured-resolver promises, zero-timer promises, or sleep loops. Linear-time tests use `expectLinearTime` from `@rakazo/contracts/test-timing` with an input big enough that a backtracking version would be far slower; never a hand-read clock against a fixed bound.
- Desktop IPC: one map + one primitive. List each channel in `apps/desktop/src/main/ipc/ipc-channels.ts` (allowed window + what a refused caller gets), answer with `handleIpc` from `apps/desktop/src/main/ipc/ipc.ts`, name it in that window's preload; never call `ipcMain.handle`/`ipcMain.on` directly. `handleIpc` refuses any caller but that window's own page before the handler runs; a handler checks the sender only to re-ask after a wait, with `sentFrom`. The app's own page is also refused while its window isn't the app window (another server opening): refused callers get the bridge method's existing "nothing done" answer, a rejection only where none exists. A channel is answered for the window being replaced (`appOrReplaced`) only when the handler acts solely on the sender's own window (e.g. window controls).
- Client-caused/actionable refusals (bad request, forbidden, not found, conflict, too many requests) are domain errors extending `ClientError` from `@rakazo/core`, carrying kind, message, and a stable code when clients switch on it. Routes let them propagate; `handleRpcError` in `apps/api/src/rpc-errors.ts` translates once; domain packages never import the RPC library. Never build an `ORPCError` in a `catch`: throw/extend the domain error, catch only the specific condition, let everything else propagate as a server error (check: `no-rpc-error-in-catch`).

## Backend, data, concurrency
- Deploys keep the previous release running after migrations (old API for seconds, old worker until jobs finish), so every migration must work with the previous code. Adding tables/columns is safe. Dropping: remove from schema and code and, in the same PR, add a migration whose first line is `-- deferred` (held back one run, applies next deploy). A dropped column must be nullable or defaulted while waiting (relax it in an ordinary migration in the same PR if needed). Rename = add + backfill new column, switch code, drop old one deferred. Code kept only for the previous release is marked `compat-shim(after vX.Y.Z)` (latest release in `CHANGELOG.md`); `pnpm checks` fails once two newer releases ship, then remove it.
- Build for many concurrent users across instances. Work starts immediately in the process that has it: never wait on a queue, worker slot, global concurrency cap, or polling loop; agent runs/LLM calls never wait for a free slot. Graphile Worker is only the durable backup: in the transaction recording the work, add a backup job with a job key and run-at = attempt timeout + small margin, then do the work directly after commit; on success delete the job, on clean failure set run-at to now (or provider retry-after); a crash lets it fire by itself. Use queue retries/backoff/scheduling/named queues (per-key ordering) instead of hand-rolled attempt/next-attempt/claim columns or polling loops. Limit only the specific resource that needs it (one bot, conversation, provider rate limit). Coordinate across processes with Postgres transactions, leases, notifications. Periodic sweeps are a ≥30 s safety net, never the main path. Delivery is at-least-once: make side effects idempotent where the provider allows.
- Clients never poll. Read once, then re-read on a server signal over the one live HTTP stream (`notifications.subscribe`): after the write commits, publish a content-free signal on a narrow topic (user/Space/bot) via the realtime fanout; the client re-reads through its normal authorized RPC. The stream signals on every (re)connect (reconnect = catch-up), plus re-read on window focus/app foreground. No timed backup re-reads or polling fallback while the stream is down; instead make missed signals rare: retry publish through brief DB outages, end the stream when a subscription fails so the client reconnects. Timers only for non-data-reads: clocks, presence heartbeats, short third-party waits (OAuth redirect) while someone watches.
- Evals: judge natural-language meaning/factual claims with an LLM and an explicit, versioned rubric calibrated on reviewed examples; no keyword lists/regexes/exact wording for free-form prose (check: `no-keyword-graded-evals`). Deterministic assertions for observable effects and structured output. Judge calls opt-in, provider-neutral, cost reported separately; judge errors = unqualified, not pass.
- A/B tests (our deployment only): register in `packages/contracts/src/experiments.ts` (first variant = control), read with `experiments.variant(key, subjectId)` on the API, pass `experiments.tags(...)` on the events judged. Runs only when `EXPERIMENTS` lists its key; self-hosters/local see control. No browser SDK or vendor flags; the analytics adapter translates tags.

## UI / UX
- Keep UI and copy minimal; show advanced capability progressively; no explainer text repeating the interface. Frontends express intent and render state; backend owns orchestration, authorization, validation, retries, recovery, provider translation. Concise accessible names for controls when needed.
- Every visible word is UI: start by asking what can be removed; prefer progressive disclosure to persistent explanation/status chrome. Review the screenshot with `.agents/skills/ux-declutter/SKILL.md` before calling UI done. A PR adding user-facing copy must quote it, justify it, and say why removing it or showing it only when relevant wouldn't work.
- Colors: semantic tokens in `@rakazo/ui-tokens` (background, card, muted, border, primary, destructive, …), one TS source generating `tokens.css`; never hardcode a product hex or use `[var(--…)]` arbitrary values.
- Web/Electron: shadcn/ui on Base UI, vendored into `packages/ui-web` via `pnpm exec shadcn add` from the official registry only (third-party registries = supply-chain risk). Reuse before hand-writing chrome: `SectionHeading` for section headings; `OptionSelect` for dropdowns over a fixed list (never the browser select); `FieldGroup`/`Field`/`FieldLabel` for forms (no hand-spaced labels); `apps/web/src/components/ai/` for AI moments (loading, shimmer, success).
- Button, select, Input, InputGroup take height from the `size` prop, never a height class (`h-*`, `min-h-*`, `size-*`) in `className`; each size name is one height everywhere (`packages/ui-web/src/lib/control-size.ts`) (check: `no-control-height-classes`).
- App is monochrome: primary is ink; status colors are destructive/success/warning; bots carry the only identity color.
- Mobile is native-first: Expo Router, Expo UI, native sheets/menus/alerts/pickers where available; custom surfaces (thread, composer, avatars, cards) use plain StyleSheet with shared tokens via `apps/mobile/lib/appearance/appearance.ts`; system chrome stays PlatformColor via `lib/native/native.ts`. Mobile may diverge from web when the native pattern is better. Use built-in native iOS controls (@expo/ui SwiftUI, Liquid Glass, native header items, context menus, alerts, pickers, switches) instead of custom RN pills/buttons.
- Marketing pages (`apps/www`, Astro): no new tests or CI screenshots beyond the existing homepage screenshot suite; may name third-party vendors/providers (product vendor-name and UI-test rules don't apply). Check visually and with a build.

## Testing
- Don't run the desktop Playwright suite (`pnpm --filter @rakazo/desktop test:e2e`) on a maintainer's machine (opens real Electron windows, steals focus on macOS); run only tests covering your change locally; CI's virtual-display job runs e2e. Web e2e (`pnpm test:e2e`) is also left to CI: update specs, push, read the CI run.

## PRs and review
- One feature or fix per PR (large is fine; bundling unrelated features is not).
- Don't edit `CHANGELOG.md` in feature PRs; the release skill (`.agents/skills/release/SKILL.md`) writes it from merged PRs, so write `## What`/`## Risk` for that reader.
- Feature PRs change UI strings in code only: never run `intl:extract` or edit `messages.po`. Untranslated strings show in English; a main-branch workflow keeps one "Update translation catalogs" PR in step; translations go there or in a translation-only PR. Exception: adding a UI language commits its new catalog.
- PR description format (author voice, never third-person about the maintainer; <~350 words unless security/migration-heavy): `## What` (short plain paragraph, readable by someone who's never seen the code) → `## Why` (product reason in plain words: what was wrong/missing, who it hurt) → `## Changes` (behavior and decisions, not file/library tours; ≤~8 bullets) → `## Risk` (only if there is one: security, migrations, limits, irreversible effects) → `## Tested` (short paragraph: kinds of tests run, what wasn't tested).
- UI PRs: embed the CI E2E screenshot showing the change (`pr-watch` explains how); add the web test opening that screen if missing. Native-only mobile UI CI can't capture: never link an unrelated web screenshot; for large native changes add a flow to the iOS screenshot catalog. Attach any screens you captured while verifying (simulator/emulator/browser) unless they show private data; say so only when you have none. Never add feature-specific flags, runners, or fake services to shared test/screenshot tooling to capture one screen; if existing fixtures can't show it, say so.
- After opening a PR, stay with it until CI and review bots finish (passing checks ≠ review done). Follow `.agents/skills/pr-watch/SKILL.md`: run `pr-digest --watch` as one backgrounded call that blocks until a new review comment/check failure or terminal checks on the head commit, act on its verdict, watch again. No foreground timer polling. Fix every actionable issue, push, repeat. Don't merge with bots pending or issues unresolved. Ignore the Vercel "Authorization required to deploy" failure on fork PRs.
- Review bots ask how to make code work, never whether it should exist: before fixing a finding, decide if the flagged code belongs; remove speculative/unrun/out-of-scope code rather than building more; refute wrong findings with evidence.
- When reviewing a PR, judge it against this file: recommend removing code that can't work or doesn't belong; flag undisclosed changes (new vendor/provider presets, dependencies, test runners, env vars, edits to shared tooling).
