# GOAL — 2026-09-28

## Objective

Make Hivemind agents **persistent across chat turns** by keeping one OMP RPC process alive per configured agent.

Right now Hivemind proves the basic meta-harness idea, but each turn creates a fresh OMP process. That means the "persistent agent" part of the architecture does not exist yet. This is the next milestone.

## Why this is the next step

The current POC already has:

- a Rust CLI,
- multiple configured agents,
- an OMP runtime adapter,
- per-agent model/reasoning/fast settings,
- concurrent fan-out of one user message to multiple agents.

The missing foundation is **runtime/session lifetime**. Until an agent survives across turns, adding agent-to-agent messaging, dynamic spawning, tasks, memory, or more runtimes will just stack features on top of disposable processes.

## Goal

A configured Hivemind agent should own one live OMP RPC session for the duration of the Hivemind chat process.

Example:

```text
Hivemind starts
  ├─ Maomao  -> OMP process/session A
  └─ Albedo  -> OMP process/session B

You> hello
  ├─ session A receives "hello"
  └─ session B receives "hello"

You> what did I just say?
  ├─ the SAME session A receives the new turn
  └─ the SAME session B receives the new turn
```

Do not spawn a new OMP process for every prompt.

## Implementation direction

Refactor the current stateless runtime path into a persistent session model.

A sensible shape is:

```text
Hivemind CLI
    |
Runtime/Agent Manager
    |
    +-- Agent worker: Maomao
    |      owns OMP RPC child + stdin/stdout
    |
    +-- Agent worker: Albedo
           owns OMP RPC child + stdin/stdout
```

Each agent worker should own its runtime process and handle prompts sequentially. Hivemind should still dispatch a user turn to all agents concurrently.

Prefer a runtime-agnostic contract such as a session abstraction rather than baking OMP process management directly into the CLI.

For example, conceptually:

```rust
trait HarnessSession {
    async fn prompt(&mut self, input: &str) -> Result<String>;
    async fn shutdown(&mut self) -> Result<()>;
}
```

The exact API is up to the implementation. Keep it small.

## OMP behavior

For an OMP-backed agent:

1. Spawn OMP RPC once when the agent session starts, or lazily on its first prompt.
2. Apply the configured model and reasoning settings to that agent process.
3. Apply `fast` once during RPC initialization when explicitly configured.
4. Wait for the RPC `ready` event before accepting prompts.
5. Send every later user turn through the same RPC process.
6. Read the assistant result without destroying the process.
7. Shut the child down cleanly when Hivemind exits.
8. Do not leave orphaned `omp` processes.

Verify whether OMP's `--no-session` only disables on-disk session persistence or also affects in-process conversational context. Keep it only if the live RPC process still retains turn context.

## Required behavior

Preserve all existing behavior:

- multiple agents,
- concurrent responses between different agents,
- `model`,
- `reasoning`,
- `fast = true`,
- `fast = false`,
- omitted `fast`,
- agent workspace,
- system prompt,
- `/agents`,
- `/help`,
- `/quit`.

An individual agent must process its own prompts in order. Do not allow two prompts to race through the same RPC stdin/stdout stream.

## Failure handling

For this milestone, keep recovery simple and deterministic:

- If an agent cannot start, report which agent failed and why.
- If an OMP child dies while handling a turn, surface a clear per-agent error.
- Do not silently create a fresh session and pretend conversational state survived.
- Clean up remaining child processes on exit.

Automatic restart/recovery can be a later goal.

## Acceptance criteria

The work is complete when all of these are true:

1. `cargo test` passes.
2. `cargo clippy --all-targets --all-features -- -D warnings` passes.
3. Start Hivemind with at least two OMP agents.
4. Send:

   ```text
   You> hello, remember the word pineapple
   ```

   Both agents reply.

5. Then send:

   ```text
   You> what word did I ask you to remember?
   ```

   Both agents answer from their own previous live conversation context.

6. Each agent uses the same OMP process/session across both turns.
7. The two agents remain independent from each other.
8. Exiting Hivemind leaves no orphan OMP child processes.

## Tests to add

Add tests around the new session lifecycle where practical:

- per-agent configuration is applied at session startup,
- multiple prompts reuse one session,
- prompt ordering is preserved for one agent,
- two agents can run concurrently,
- shutdown cleans up the runtime,
- RPC errors are attributed to the correct agent.

Avoid tests that require a real provider/API where a fake transport or process fixture can prove the behavior.

## Non-goals for this goal

Do **not** expand scope into these yet:

- agent-to-agent messaging,
- dynamic agent spawning,
- `<spawn params=...>`,
- task delegation,
- shared memory,
- persistent memory database,
- Codex/Claude/Pi adapters,
- GUI/TUI,
- streaming UI,
- distributed/remote agents,
- autonomous orchestration.

Those come after persistent runtime sessions are solid.

## Definition of done

Hivemind should stop behaving like:

```text
prompt -> create disposable agent -> reply -> destroy agent
```

and start behaving like:

```text
start Hivemind
    -> create agent sessions
    -> prompt
    -> prompt
    -> prompt
    -> shutdown sessions
exit
```

This gives us the correct foundation for the next major feature: Hivemind-controlled agent communication and spawning.
